# Observation schema 0.2.0

Historical recovered candidate schema. Current beta changes are documented in `OBSERVATION_SCHEMA_0_3.md`; the old candidate's host evidence does not qualify changed code.

Stage: PROTOTYPE IN PROGRESS. This is bounded read-only observation, not routing or output certification.

`completion` is `completed` only after project/sequence enumeration and all attempted reads finish without recorded errors; `partial` retains independently supported observations with scoped errors; `failed` means no project or project/sequence-list acquisition failure. An empty successfully enumerated project is completed. Inventory flags distinguish failed reads from verified empty arrays. A failure placeholder never proves an empty track. Diagnostics emit ARID-U-READ with a JSON observation scope and original error cause; capability Unknowns remain separate. ARID-I01 has severity Information. ARID-001 requires complete track/clip inventories and boolean mute observations. ARID-002 retains directly observed muted non-empty tracks even when other inventory is incomplete.

Project metadata is captured from the acquired project object before enumeration. Single-flight execution ignores additional clicks until cleanup. A report describes this captured project, not the project selected later. Reads are sequential and are not an atomic snapshot; project edits during a scan can affect consistency. No current-project relabeling occurs.

Sequence GUID and scan-local sequence occurrence index, track ID/index, and scan-local clip occurrence index accompany locations. Clip observations also carry sequence/track context. Timeline start/end are serialized TickTime fields from documented getters, relative to sequence start. Missing identities remain null with read errors; track index fallback is the enumeration index when getIndex fails, with that failure retained. Missing times are null with scoped errors. Occurrence indices are zero-based for this scan only, never stable host IDs. No navigation, markers or mutations are performed.

The serializer inspects only documented/allowed value fields, to depth 8, total 2048 visited values, and arrays of at most 1024 elements. Nested value wrappers, PointF x/y, Color red/green/blue/alpha, TickTime string ticks and numeric seconds are preserved. Arrays/typed arrays are supported generic data shapes, not host semantic evidence. Null stays null; undefined, BigInt, nonfinite numbers and negative zero have explicit `$type` tags. Unsafe integer numbers fail rather than claiming exact precision. Unexpected plain data fields, unsupported objects/types, cycles, throwing getters and bounds produce scoped serialization errors. No pan/balance rule is enabled.

Legacy synthetic diagnostic inputs without schema/completeness fields remain supported; diagnostic completion is unverified-legacy. These synthetic inputs are not complete host reports.
